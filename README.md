# Prism Keep

> 极简几何塔防 · Godot 4 · 纯 2D 上帝视角
> 英文名 **Prism Keep**（棱堡）—— 名字指向“要守的那座核心”，单人或多人联机都成立

80×80 格战场，大本营固定在正中 2×2 格，守满 100 波即胜利，大本营被摧毁即失败。
**全部美术（地图网格、建筑、敌人、角色、特效、UI 图标）由代码绘制，工程内不含任何图片或音频资源。**

---

## 一、运行

- 引擎：Godot **4.7**（4.3+ 均可，用到的都是稳定 API）
- 打开 `新建游戏项目/project.godot`，主场景为 `res://scenes/main.tscn`，F5 直接运行。

### 操作

所有与世界格子的互动都只作用于**角色面前一格**（朝向主导轴方向的相邻格，斜向移动时取 x / y 分量较大的一侧），画面上始终用提示框标出这一格。

| 操作 | 说明 |
| --- | --- |
| `W A S D` / 方向键 | **控制角色移动**，移动方向即面朝方向，视角自动跟随角色 |
| `F` | **与面前的空地互动（建造）**：选好建筑后按 F 放置；未选建筑 / 面前不是空地时给出提示 |
| `G` | **与面前的建筑互动**：选中查看（可升级 / 拆除），再按一次取消 |
| `I` | **靠近改造车间时**打开 / 关闭改造菜单（用技能点购买全局加成） |
| `1` `2` `3` `4` `5` `6` `7` `8` | 选中箭塔 / 金矿 / 围墙 / 寒冰塔 / 路障 / 炮塔 / 改造车间 / 喷火器（进入建造模式，幽灵预览跟随面前一格） |
| 右键 / `ESC` | 取消建造、取消选中 |
| 右上角 `1× 2× 3×` | 全局倍速（改 `Engine.time_scale`） |
| 右上角 `暂停` | 暂停 / 继续 |

## 三、场景划分

| 场景 | 职责 | 为什么这样切 |
| --- | --- | --- |
| `main.tscn` | 组装层 | 只做“世界 + 相机 + UI”三件套的拼装，方便换皮 |
| `world.tscn` | 世界容器 | 用 `z_index` 把绘制顺序写死：网格 0 → 大本营 1 → 建筑 2 → 敌人 3 → 弹丸 4 → 特效 5 → 角色 7 → 建造预览 8 |
| `hud.tscn` | UI 层 | CanvasLayer + `process_mode = ALWAYS`，暂停时仍可操作 |
| `entities/*.tscn` | 单个实体 | 根节点 + 脚本，造型全部在 `_draw()` 里画，换形状不用改结构 |
| `fx/burst_fx.tscn` | 一次性特效 | 播完 `queue_free`，不进对象池也不需要贴图 |

> 建筑、敌人、角色都没有用节点拼装外观（比如 Polygon2D + Sprite），而是直接覆写 `_draw()`：
> 一个实体 = 一次绘制调用，改动造型只改一个函数，也彻底避免了外部素材依赖。

## 四、核心实现思路

### 1. 网格与坐标（`Board`）

- 世界坐标 → 格子：`cell = floor(world / 32)`；格子 → 世界：取格子中心。
- 80×80 共 6400 格，占用表用 `Dictionary<int, Building>`，`idx = y * 80 + x`，O(1) 查询。
- 矿山格：`ores` 字典存每局随机生成的 20 个矿点（`is_ore()` 查询），只是地形标记，不阻挡通行、不参与寻路。
- 大本营占 `(39,39)~(40,40)` 四格（地图正中，世界坐标 1280,1280），这四格不可建造，且是流场源点。

### 2. 寻路：两张流场

每格存“到最近大本营格子的步数”，敌人每帧只需走向数值更小的邻格 —— 不需要 A*，也不会有路径抖动。

| 流场 | 阻挡规则 | 用途 |
| --- | --- | --- |
| `dist_normal` | 所有建筑都挡 | **默认路线**：敌人绕开一切建筑直奔大本营 |
| `dist_free` | 什么都不挡 | **兜底**：大本营被彻底围死时，沿最短路直扑，挡路的建筑当场拆（围墙只有重甲 / Boss 会强拆） |

敌人取用顺序：`dist_normal` 有值就走它，否则用 `dist_free`。
这样同时满足三件事：

1. **敌人永远优先打大本营** —— 只要还有路，它绝不会去碰沿路的塔和墙；
2. 被围死时不会卡死，会顺着直线一路拆过去（围墙挡住的普通敌人会绕行或原地等待）；
3. 玩家用塔把路堵死也无效，敌人会拆塔 —— 从机制上消灭“无敌龟壳”的挂机打法。

BFS 细节：8 邻域 + 对角“不许贴角穿墙”（对角线两侧的正交格都得能走），所以敌人不会从墙角缝隙挤过去。
重算做了 0.25 s 节流（`mark_dirty()` → `_process` 里合并重算），批量拆墙时不会一帧内反复全图 BFS。

### 3. 敌人（`Enemy`）

- 四类几何体：圆=普通、三角=疾行、方=重甲、五边形=Boss；同波次线性成长（`hp ×(1+0.16w)`）。
- 被寒冰塔命中会**冰冻**：冻结期间无法移动与攻击，Boss 只有 30% 的冻结时长（`freeze_mul`）。
- **灼烧**：被喷火器 / 熔岩点燃后每秒燃烧自身最大生命值的 1%（改造车间可加成，岩浆中翻倍），持续 10 秒，按整秒结算，冻结中仍持续燃烧。
- 移动：目标 = 下一格中心 + 每只固定的随机偏移（±0.26 格），自然散开，不需要邻居排斥的 O(n²) 计算。
- 行为四分支：
  1. **踩到大本营** → 啃基地（最高优先级目标）；
  2. **身边 8 格有路障** → 停下来攻击它（嘲讽，所有敌人一视同仁）；
  3. **还有路** → 沿 `dist_normal` 走，不碰任何建筑；
  4. **被围死** → 先看身边 8 格有没有炮塔，有就**优先拆炮塔**；没有就沿 `dist_free` 直扑大本营，拆掉挡路的建筑 —— 但**围墙普通敌人不会攻击**（重甲 / Boss 才会强拆），打不动就找空邻格绕行，绕不开就原地等待（交给围墙后的塔输出）。
- 朝向用 `lerp_angle` 平滑，绘制时 `draw_set_transform(0, _face, scale)` 让三角形/五边形转向，血条再转回来。

### 4. 玩家角色（`Player`，占位符）

- 顶视圆形身体 + 朝向楔形 + 双脚摆动，纯 `_draw()` 拼的，方便以后换成真正的美术。
- WASD 自由移动（190 px/s），**分轴碰撞**：撞到建筑时只停下被挡的那个轴，可以贴着墙滑。
- 面前一格：`front_cell()` 取朝向主导轴方向的相邻格，是 F / G 键互动的目标；移动被挡时朝向仍会更新，可以原地转身。
- 目前**没有任何攻击手段**，只是一个“人在战场上”的锚点，供后续做成英雄单位。
- 相机 `_process` 里 `position.lerp(player.position, 1-exp(-10δ))` 平滑跟随，再夹到地图边界内；缩放固定 0.85，滚轮与其它途径都不能改变视野大小。

### 5. 战斗与建筑（`ArrowTower` / `Projectile` / `Building`）

- **所有建筑都有血量**：箭塔 260、寒冰塔 220、金矿 220、围墙 420，受击闪白，被摧毁时爆散并 `Board.unregister()` 触发重新寻路。
- 箭塔索敌节流到 0.12 s 一次，取射程内**最近**的敌人；炮塔角度 `lerp_angle` 平滑跟随。
- 寒冰塔与箭塔共用索敌逻辑，发射**冰晶弹**：命中除造成伤害外，还会把敌人冻结 1.0 s（Boss 0.3 s），冻结期间无法移动与攻击。
- **炮塔（重炮系）**：血厚炮沉（300 血），3 级后花 150 金二选一定型 —— **重型炮**单发 120 攻击单体并**优先锁定血量上限最高的敌人**（Boss 克星）；**迫击炮**射程扩至 8.5 格，炮弹落在固定点对 4×4 范围内所有敌人溅射 45 伤害，**优先轰击敌人最密集处**（以"溅射圈内敌人最多"的落点为准）。
- 弹丸有两种模式：追踪式（箭塔 / 冰晶 / 重型炮）跟住目标结算单体；落点式（迫击炮 / 冰暴塔）飞向固定坐标，到达后对溅射半径内所有敌人结算群伤并播放爆散。
- **喷火器（火系）**：朝面前 45° 扇形喷射，锥内敌人吃少量直接伤害并被**点燃** —— 每秒燃烧自身最大生命值 1%，持续 10 秒（按整秒结算，冻结中仍燃烧）。3 级后花 130 金二选一 —— **烈炎塔**射程扩至 7 格（火舌更远）；**熔岩塔**改为向敌人密集处投掷岩浆，岩浆池持续 5 秒、覆盖约 3 格，池内灼烧**翻倍（2%/秒起）**，走出岩浆仍残留灼烧。
- **寒冰塔分支**：3 级后花 140 金二选一 —— **冰暴塔**发射冰暴弹，落点爆炸覆盖 3×3 格，所有命中敌人受 35 伤害并被**减速 50%**（2.5 秒，与冻结叠加为独立状态）；**不朽塔**用激光锁定单个敌人持续攻击，目标被**冻结在原地**，伤害随锁定时间线性提升（+40%/秒；增伤上限分敌人类型 —— Boss 3 倍、精英怪（重甲）5 倍、其余无上限），目标死亡或丢失后伤害回归原位。
- **满级箭塔分支**：3 级箭塔的详情面板出现两个“定型”按钮，花 120 金二选一 —— 快速射击箭塔（间隔 0.5s → 0.16s，双联管外观）与大范围射击箭塔（射程扩至 8 格，伤害 ×1.15，长管外观）。分支即改 `kind` 并封顶，不可再升级、不可再分支；拆除返还按累计投入（含分支费）计算；敌人被围死时的“优先拆炮塔”判定对分支塔同样生效。
- 弹丸是追踪式的：每帧朝目标当前位置飞，命中即 `target.take_damage()`（冰晶弹额外调用 `apply_freeze()`）；目标死亡/释放则自毁。

### 6. 建筑查看（`BuildController` + HUD）

- 互动目标固定为**角色面前一格**（`Player.front_cell()`：朝向主导轴方向的相邻格），画面上用提示框常亮标出 —— 空地淡框、建筑亮框。
- 按 G → 取面前格的建筑 → `GameState.building_selected.emit(b)`，再按一次取消；面前格里的塔还会顺带显示射程圈。按 F 面前却是建筑时会提示改按 G。
- UI 层：左侧弹出详情面板，**血量条每帧实时刷新**（因为它可能正在被拆），并显示该建筑的核心属性：
  - 箭塔：`攻击力 19  每秒 38`、`射程 5 格`
  - 寒冰塔：`攻击力 10  冰冻 1.0 秒`、`射程 4 格`
  - 金矿：`产出 3 金 / 2 秒`
  - 围墙：阻挡说明
- 详情面板底部有**升级 / 拆除**按钮：
  - 升级：仅箭塔 / 寒冰塔 / 炮塔开放（最高 3 级），费用 = 1.1 ×（建造价格 + 前一次升级价格），首次升级即 1.1 × 造价；每级伤害 ×1.5、**射程 +1 格**、血量上限 +30% 并回复等量血量，寒冰塔冻结时长额外 +0.25s，塔身下方出现等级星标
  - **分支定型**：满级箭塔 / 炮塔 / 寒冰塔面板额外出现定型按钮（各自的二选一分支），点击消耗对应费用完成分支，面板即时切换为新塔的名称与属性
  - 拆除：返还 = 累计投入 × 返还比例，比例随等级递减 —— 1 级 70% → 2 级 55% → 3 级 40%
- 建筑被拆毁时面板自动隐藏（`is_instance_valid` 判定）。
- 右上角**小地图**：整张地图的 160×160 缩略，实时显示大本营、矿山、建筑（各自配色）、敌人、角色白点与当前视野框，纯代码绘制、鼠标穿透。

### 7. 建造（`BuildController`）

- 按 1~7 / 点建造栏进入建造模式，**幽灵预览固定跟随角色面前一格**：绿/红描边 + 半透明填充，塔类额外画出射程圈；面向想建的位置按 F 放置，松开仍保持建造模式可连放。
- **围墙 / 路障**：同一场景（`wall.tscn`）两种形态，建造时按所选类型设置 `barricade` 标记再入树 —— 围墙（12 金 / 420 血）被动阻挡，路障（20 金 / 700 血）嘲讽吸火力。
- 放置顺序很关键：**先 `add_child()` 让 `_ready()` 初始化属性，再 `place(cell)` 登记到棋盘** —— 否则围墙的 `is_wall` 还没赋值，`Board` 会把它当成普通建筑登记。
- 非法落点（越界 / 大本营 / 已占用 / 钱不够）直接拒绝并弹提示。
- **金矿只能建在矿山格上**：每局开局 `Board.generate_ores()` 随机生成 20 个矿点（避开大本营），地面画淡金底 + 岩石矿粒标记，选中金矿时全部矿点高亮、幽灵预览只在矿点上变绿；其余建筑仍可放在任意空格。
- 原地也能转向：即使移动被墙挡住，朝向仍跟随输入方向更新，贴着墙就能选中想互动的格子。

### 8. 波次（`WaveManager`）

- 第 w 波：数量 `min(10 + 3w, 90)`，按权重混入疾行/重甲，每 10 波追加 Boss。
- 出生点：每波随机选 1~4 个方向（波次越高越多），在地图四边取随机格子，再沿边缘抖动 ±5 格，保证是“四面八方涌来”。
- 出生表是 `{时间, 类型, 格子}` 的数组，`_process` 里按时间弹队；队列空且场上无敌人 → 本波清空。
- **提前迎战奖励**：准备期间点击「下一波」立即开战，获得 `剩余秒数 × 10` 的金币（与倒计时显示一致向上取整，首波准备期同样有效）。
- 第 100 波清空 → `GameState.finish(true)`；大本营血量归零 → `finish(false)`。

### 9. 渲染与纯代码美术

- 网格不画 6400 个矩形，而是**只画视口内的横竖线**（用 `canvas_transform.affine_inverse()` 求可视世界矩形），每帧几十条线。
- 实体造型：`_draw()` 里的 `draw_rect / draw_circle / draw_colored_polygon / draw_arc / draw_line`。
- UI 图标：`Art.build_icon()` 在 64×64 的 `Image` 上做多边形逐像素填充，再 `resize` 到 28px 得到近似抗锯齿的图标。
- 中文字体：`SystemFont` 依次回退 `Microsoft YaHei UI / PingFang SC / Noto Sans CJK SC / SimHei`，不打包字体文件也不会出现方块字。

## 七、联机路线（预留）

当前是单机实现，但结构上已经为“**服务器权威 + 指令同步**”留好了口子，将来加联机不需要推翻重写。

### 已经合适的部分

- `Board` 本质是纯函数式棋盘：**给定同一份建筑列表，两端跑出的流场完全一致**。
  所以客户端只要收到“某格放了 / 拆了建筑”，本地重算即可 —— 敌人路径完全不用同步。
- 敌人位置由流场推导，只有 `_offset`（散开偏移）和 `_attack_cd`（首次攻击相位）用了随机数，补一个种子就能对齐。
- `GameState` 已经集中管理金币 / 血量 / 波次，天然就是“权威状态”的容器。

### 改造时要动的地方

1. `BuildController._try_place()` 拆成：**发指令 → 服务器校验（金币 / 格子 / 是否把路堵死）→ 广播 → 各端 `Board.register()`**。
2. `WaveManager` 只在服务器跑，只广播 `{波次, 类型, 出生格, 随机种子}`，客户端本地生成敌人。
3. 倍速从 `Engine.time_scale` 改成服务器下发的 `game_speed` 变量，客户端只读。
4. `Player` 加 `peer_id`，相机绑定“本机角色”，`get_first_node_in_group("player")` 换成按 peer 查找。
5. 所有 `randf() / randi()` 收拢到统一的 `RandomNumberGenerator`，种子由服务器下发。
6. `GameState` 的写操作（加金币、扣血、结束）只允许服务器调用，客户端只读 + 播表现。
